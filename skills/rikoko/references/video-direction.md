# Video direction with the host agent

Gemini is the original-video analyst; the host is the target director. rikoko executes operations and returns evidence. Neither a job status nor a technical check is a visual opinion.

Before generation, translate the user's purpose into target shots. Source shot count, cuts and seconds are observations, not a required target timeline. Use `production_plan_validate` and `production_plan_save`; assign stable target shot IDs, one main action, initial state and final state. Source shot IDs can be empty or many-to-many. Name persistent objects consistently. Use `unknown` when evidence is missing and explain intentional time jumps.

Choose inputs by responsibility:

| Input              | Responsibility                                     |
| ------------------ | -------------------------------------------------- |
| Character image    | Identity, wardrobe, physical features              |
| Product image      | Geometry, visible markings, material and color     |
| Scene/style image  | Only the declared setting or appearance properties |
| First/last frame   | Actual boundary states and framing                 |
| Motion excerpt     | Explicitly selected action, camera path or rhythm  |
| Source observation | Understanding; no generation input unless selected |

A remake does not require sending the source video to the video model. A source frame is opt-in using `useSourceComposition=true`; target product and scene references normally establish the image. A motion excerpt requires `motionPurpose` and `motionExclusions`, and should include preparation and completion. Do not use an unrelated operation as an action reference. Compare action types in `generation_prompt_preview` and resolve mismatch warnings.

Use `production_shot_prompts` to carry the saved target states into image and video prompt drafts. Inspect actual first/last frames before relying on them. `generation_prompt_preview` supports distinct text, first-frame, first/last-frame, reference, motion-transfer and camera-transfer wording. Transfer modes are prompt strategies: the selected provider must still expose a compatible `reference_to_video` input route. Use its returned prompt and ordered reference bindings. Do not paste cloud analysis JSON into a video prompt.

For protocol `rikoko-prepared-generation-v1`, call `generation_prepare` with `input` containing the exact preview prompt, model, ordered reference asset IDs/roles, supported `parameters` and `target={width,height,aspectPolicy:"match"}`. Also pass the preview's normalized `direction`. For a saved target shot, pass `plan={planId,expectedVersion,shotId,stage:"video"}` with `production_shot_prompts.video.direction`. For boundary images use `stage:"first_frame"` with `.image.direction` or `stage:"last_frame"` with `.lastFrame.direction` and an image model. First-frame drafts describe only the starting state; completed-action requirements belong to the video. Changes to target action/states/references belong in the plan first. For non-remake work, handwritten or changed wording requires `promptOverride.reason`; this does not waive mode, parameter, target or reference checks. Set a direction reference's `usage="analysis_only"` when it must not enter the provider request.

Check `capabilities` for `allowedParameters`; do not invent upstream fields. First/last-frame aspect comes from the image. A mismatch requires fixing the image/parameter or an intentional `contain`/`allow_crop` policy. A preparation saves the exact logical operation, full prompt, template/compiler versions, plan dependency, reference hashes, provider field/array ordering and model configuration digest. The preview shows public output controls; private provider configuration is hash-bound, and temporary delivery URLs are resolved only at execution. Check `readyForSubmission`. Cloud preparation negotiates `rikoko-cloud-preparation-v1`: the server previews declared reference hashes/metadata without uploading files, then quotation uploads and verifies actual bytes into an immutable bound request. Older gateways fail with `PREPARATION_PROTOCOL_UNSUPPORTED`; keep the preparation fields and reconnect a compatible server.

Pass the returned `input` unchanged, including `preparedRequestId`, to `quote_create` and then `job_submit` under the existing cost-agreement rules. A storyboard can use the same record through `reference_storyboard_quote(preparedRequestId=...)`. Read it after reconnection with `record_get(type="generation-preparation",id=...)`. Quotation, submission and the worker recheck dependencies without recompiling saved wording. Dependency changes require a fresh preparation and quote; retrying the same submitted job uses its original idempotency key. Reference-input video generation requires preparation by default; all video generation requires target dimensions. Only an administrator setting `RIKOKO_ALLOW_LEGACY_GENERATION=true` may enable legacy unprepared generation. It never disables storyboard target-plan requirements or final-delivery review. No model calls occur during preview/preparation; preparation persists an account-owned record (and a cloud draft in official mode) and needs write permission. Model availability, provider calls and billing remain separate.

Saving a target plan creates a default scoped project (`productionProjectId`). Preparation with that plan inherits the scope and canvas automatically. To attach an existing project or change review requirements, call `production_scope_save` with its plan ID/version and current scope version (`0` initially). Use `input.production={projectId,scopeVersion,shotId}` together with the matching preparation plan. Scope is saved on the project and cannot be disabled on individual requests. Updating a bound plan/scope synchronizes its version to the connected cloud before saving; reconnect the original connection if synchronization is unavailable.

Inspect and accept each source asset, then call `production_asset_assign` for the exact project, scope and shot. `use="prepared_generation"` requires completed output prepared for that target. Imported or experimental media needs `use="external"` and explicit permission in scope `requirements.allowedAssetUses`. Use `reference_adapt` with `plan={planId,expectedVersion}` and `replacements[].productionShotId`; it assembles target shots in plan order and returns the scoped `projectId`. Pass it to the first `workspace_commit`. Source-only IDs must map unambiguously. Existing scenes can use `scenePatchSchema` through `revision_revise`. Planned title cards must declare shot `visualKind="graphic"`. Scope changes invalidate assignments and revision acceptance. Use `workspace_validate` and `workspace_result(purpose="final")` after reviewing the actual rendered revision; draft rendering does not confer formal acceptance.

After generation, inspect the actual clip. Keep its full duration by default. `reference_adapt` uses complete replacement videos unless you specify a selected range or `timingPolicy="fit_target"` with a target duration. Fit changes whole-clip playback speed within 0.25–4. Choose cuts from the action, not the reference stopwatch. Keep a short readable settled result. Verify audio, captions and effects after temporal edits; do not carry obsolete word timing onto replaced speech.

Only repair the failed shot or edit. Preserve accepted media and prior versions. Report what is observed, what is inferred and what remains unknown.


## Gemini-to-host remake handoff

1. Obtain a completed Gemini `recreate` report (merge prepared segments when needed). Read `reference_analysis_get(section="handoff")` through all pages. Retain `binding.analysisAssetId` and `binding.analysisSha256`; processing windows and estimated timestamps do not dictate target cuts.
2. Author `plan.remake` with the binding, `productFacts` supplied by the user or supported target assets, and `requirements`. Each requirement has a stable `id`, `mode` (`preserve`, `adapt`, `free`), `origin` (`reference` or `user`), `description`, `sourceShotIds`, and `evidenceIds`. Reference requirements need both source shots and observed evidence. Preserve the required mechanism/outcome; adapt the stated feature with an explanation; free permits change and need not map to a target shot. These are host declarations, not automatic semantic judgments.
3. Each target shot needs `purpose`, `initialState`, `action`, `actionStages`, `endState`, `camera`, `acceptanceCriteria`, and `requirementUses=[{requirementId,application,changeReason?}]`. All preserve/adapt requirements must be covered; adapt requires a reason. Source mapping may split or combine shots; together the mapped target shots must cover the requirement's source shots. New target shots may have empty source mapping. Do not copy unsupported product mechanisms from the reference.
4. Relevant coverage gaps block production. Relevant unknowns require Gemini reinspection, or `unknownDecisions=[{index,disposition:"not_applicable",reason}]` explaining why they do not affect this remake. `blocking` remains blocking. A host explanation never turns unseen action into verified evidence. Retain the original report; use a new bound report for reinspection.
5. Validate/save, bind the formal project scope, and compile with `production_shot_prompts`. Its handoff contains source evidence, selected requirements and neighboring target states. Do not add neighboring actions to this shot. Remake generation requires the exact compiled prompt; change the plan to revise it. Source/requirement/product-fact/uncertainty changes need `remake.changeReason`, a new plan version, scope binding, preparation and acceptance.
6. Recheck every requirement and the shot's acceptance criteria against actual generated media and the rendered cut. For rendered-cut `media_review(revisionId=...)`, supply `requirementChecks=[{requirementId,status:"pass"|"fail"|"unknown",reason}]`; all preserve/adapt requirements must pass before acceptance. Use `unknown` when you cannot see. Report protocol validation separately from visual fidelity; only a capable reviewer can judge the latter.

The local service verifies owned report bytes/hash, completed analysis lineage, source metadata/hash and selected evidence. Cloud generation receives an explicitly acknowledged **host-verified snapshot**, not the source report or video by default. An older gateway or a changed/missing snapshot blocks preparation; do not strip fields to proceed. Both endpoints must be upgraded for this contract. Host-independent Gemini routing does not imply Gemini availability, billing approval, or proven output quality.

## Compiler and model reference syntax

Keep `initialState` and `endState` as structured object maps in the plan and returned direction. The compiler renders them into readable sentences; preparation compares the objects, not JSON text. The source storyboard returns `sourceObservation` with `readyForGeneration=false`. Its `authoredDrafts` are notes, not a generation input. Always compile the independently authored target plan.

Pass the actual video `model` and optional `imageModel` to `production_shot_prompts`, or `model` to `generation_prompt_preview`. Read `generationInput.referenceSyntax` in the profile: `kling` uses case-sensitive `@Image1`, `@Video1` with separate image/video numbering in provider input order; `descriptive` uses ordinary prose. MiniMax first/last frames use “The first frame” / “The last frame”, with no invented `@` tokens. A preview without a model is generic; preview again with the selected model before preparing.
