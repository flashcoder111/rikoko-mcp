# Visual review and delivery

Review contract: v2. Read `capabilities.visualReview` before relying on these fields; installed clients may still use an older runtime.

Use the host adapter to establish whether actual inspection pixels reach the model. `structuredContent` alone contains metadata, not those pixels. When forwarding MCP results through a tool runner, preserve its image blocks. If using user review, present the actual preview and ask about specific unresolved criteria; record only what the user confirmed for that exact asset/revision, with `reviewer="user"`. A general “continue”, quote acceptance, or approval of an earlier revision is not a visual review. `reviewer="host_agent"` requires actual visual evidence available to the reviewer; document a separate vision review's provenance in notes rather than claiming personal observation. Neither sampling nor visual review proves audio quality.

1. Call `media_inspect` on each generated image/clip. It returns real MCP image blocks, source hashes, requested timestamps and an inspection ID. Use `count` (default 3) for uniform sampling OR ordered `timesMs` for critical events, up to 12 samples per call; both support `layout="grid"`. `requestedTimeMs` and the compatibility alias `sourceTimeMs` are seek requests, not verified decoded frame timestamps. Unsampled intervals remain unobserved.
2. When analysis calls a shot static, use `claimedStatic=true` with at least three samples. A difference warning contradicts a confident static claim; low difference cannot establish that no motion occurred between samples. Check the actual pixels.
3. Record an honest `media_review` with exact asset and inspection IDs, reviewer and notes. Each check (`actionComplete`, `framing`, `continuity`, `noArtifacts`) has `{status: "pass" | "fail" | "unknown" | "not_applicable", reason?}`. Explain every status except pass. If unable to see, record unknown checks with `decision="unreviewed"` and `inspectionIds=[]`; do not invent visual findings. An intentional hold can mark action completion not applicable with a reason. Acceptance is host/user judgment.
4. Render a preview. `workspace_validate` lists each source interval, inspection request, cropped area fraction, omitted tail and placeholder. `visualKind="graphic"` explicitly declares a deliberate brand/title card; it renders a plain background with the composition's authored text. Never label a missing product shot as a graphic to bypass validation.
5. Inspect the actual rendered result and cut boundaries. Source images alone cannot prove final framing, transitions, captions or audio work. Record `media_review` with `revisionId` and the rendered video's asset ID. New revisions invalidate acceptance; a rejected review replaces previous acceptance for the same revision.
6. Request `workspace_result` with `purpose="final"`. It requires a production scope, mapped/assigned accepted assets, preserved action intervals, and current rendered-revision acceptance. `purpose="preview"` remains available during iteration and must be described as a preview. Preserve the exact returned clickable workspace link alongside native attachments; do not open a browser automatically.

Technical output checks report measured aspect and duration misses after download. They preserve generated bytes for review and do not declare visual success. No automatic regeneration or paid vision service is triggered.

For video `actionComplete=pass`, declare `actionRanges=[{startMs,endMs,holdMs,reason}]` for the actual critical action intervals. `holdMs` defaults to 200 ms for a readable settled result; an explicit 0 is appropriate only when no hold is intended. Keep action plus hold inside the reviewed interval. Inspect preparation/contact/completion and hold with requested sample gaps no greater than 250 ms; use multiple bounded calls and supply their inspection IDs. This is an initial sampling policy, not a model specification or a guarantee of motion correctness. Fast or uncertain actions need closer inspection. Three overall frames alone do not establish a completed action.

An optional review `range` accepts only that excerpt; it cannot certify the whole asset or a final revision. A later rejection or uncertainty in an excerpt revokes whole-asset acceptance until re-reviewed. Final-cut reviews bind `revisionId` and must cover the whole rendered output. Historical v1 accepted records remain stored but require v2 review before final delivery; reinspection reuses media and never regenerates it. Legacy boolean inputs are normalized but do not bypass evidence requirements.

`workspace_validate` checks the source-time union of scenes using the same asset and target shot, accounting for trim and speed. Omitting any part of an accepted action interval or its hold produces `ACTION_RANGE_CUT` (error), even if a rendered-cut review was accepted. Contiguous split scenes can jointly preserve the action. `DISCARDED_TAIL` remains a warning for otherwise unclassified discarded footage.

Preview results do not emit Hermes `MEDIA:` lines, native attachment instructions, or final delivery language. `workspace_export` defaults to final and runs the same gate; explicitly requesting `purpose=preview` saves inspection files only.
