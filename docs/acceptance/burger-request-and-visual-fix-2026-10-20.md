# 汉堡任务输入绑定与视觉修复验证

日期：2026-10-20。用户授权按根因优先级修复、检查，并允许图片/视频生成总预算不超过 USD 10。

## 完成范围

本轮在原分支完成本地代码和指导文档修改，保留工作区原有改动。未创建分支、提交、推送或部署。常用 4310 服务仍运行原冻结版本；本次实际运行和生成通过独立的 4311 验证服务，数据目录为 `.data/burger-fix-2026-10-20/`，未覆盖旧作品或数据库。现有工作台功能没有发布。

### 1. 当前附件与任务绑定

新增 `packages/core/src/production-request.ts`。`production_plan_save` 接受 `request={requestId,expectedVersion,excludedAssets?}`，保存请求版本和当前附件的 ID/SHA-256 快照。

- 当前附件必须出现在计划引用或音频中；不用的附件须显式给出排除理由。不能静默使用另一张产品图。
- 更新计划时继承绑定；省略 request 字段不能删除它。
- 读取生产作用域时重新核对请求版本、附件覆盖和哈希，因此准备、报价、提交和生产素材使用链路会发现过期依赖。
- 绑定只在宿主本地核验；云端继续使用既有冻结计划协议，不发送私有用户聊天记录。
- 老计划和云端镜像保留兼容性。该保护覆盖已绑定请求；系统不能发现宿主完全没有导入的附件，所以 MCP 总指引、视频指引和工具描述同时要求所有新的附件任务先建请求并绑定。

新增五项回归测试：旧图替换、编辑保留绑定、请求更新失效、字节变化/跨账户访问、明确排除及旧计划兼容。

### 2. 视觉通路和真实状态

复用并验证工作区已有的关键图片门禁、提示词职责分离、previous_end 校验及交付状态分离，没有把其他既有修改记成本轮新实现。补充 Hermes 缺陷修复指引：先分别观察原输入和出错输出，再决定修复阶段；替换后检查实际新素材与保留区间。图片路径、亮度和像素数量不能证明视觉正确。

本轮 Codex 实际看到了输入产品图及输出网格。对失败的原始吊装/铺菜分别写入 `needs_changes`；新片保留 `unreviewed` 整体验收状态，同时记录已经观察到的动作与剩余不确定性。没有制造全面通过记录。

安装中的 Hermes 结果渲染适配器通过专门测试，证明结构化结果和原生图片标记可以共存。它不证明 Hermes 当前文本模型具备视觉能力；本轮没有更换其模型、修改其配置或启动它生成回复。

### 3. 生成路线与真实对照

指引新增：对于“换产品、保留动作和运镜”，优先评估 MiniMax 的 product+motion reference_to_video 路线；保留工人参与及趣味，不能用静止/跳过工序默默替代。

本轮先使用 Hypit 成功案例的同一产品文件、四段原片、四段原提示词，提交四次 4 秒 MiniMax H3 Max 参考视频生成。保留原提示词是一次显式标记的实验性 promptOverride，不宣称经过正式 remake 来源验收，也没有剥离既有 remake 字段。这四次均有当前请求、正式项目/镜头作用域及精确准备记录。

模型家族同属 MiniMax，不表示与 Hypit 使用的上游版本、扩写和随机种子相同。本实验没有证明两个供应商完全等价。

| 镜头 | 首轮观察 | 处理与最后观察 |
|---|---|---|
| 煎肉 | 微型工人操作肉饼，蒸汽明显；没有开场提前成堡/巨型手 | 保留；人物表演和运镜仍偏克制 |
| 吊装 | 末帧肉饼仍悬在底包上方 | 一次 5 秒重试：实际完成落座、撤架；约 4.2 秒才落座，未遵守第一秒落座的精确时机 |
| 铺菜 | 开场已有上盖，随后出现真人手 | 一次 4 秒重试：强调敞口初态、微型工具搬运；采样中由设备和工人完成铺菜，无真人手或上盖；部分初始支撑被遮挡 |
| 收尾 | 淋酱、一次合盖、撤工具、工人庆祝、拉远 | 保留；后期只叠加一处 rikoko |

四段最终采用素材按约 200ms 间隔抽帧，实际看过 9 张密集网格；另检查最终合成的切点、结束状态和文字。采样不是每帧审查，没有主观听审；验证片关闭原生音轨，故为静音视觉样片。跨镜头面包形状、配料及设备细节尚不完全一致，不声称整体质量已经超过 Hypit。

全部最终素材通过 `prepared_generation` 分配到原验证项目，没有以 external 绕过来源约束。镜头保留完整视频帧，只移除不足一帧的音频容器尾部填充；没有裁掉落座/撤工具事件。

## 验证结果

- `pnpm build`：通过。已有两项中文字体路径构建警告，资源在运行时解析。
- 全量测试：98 个文件通过，1 个文件跳过；747 项通过，1 项跳过。
- 对跳过的已安装 Hermes 适配器测试补充指定路径执行：1 项通过。
- 最后工具文字更新后，相关 5 个文件的 24 项回归测试全部通过，类型检查再次通过。
- 实际 HTTP 链路三项负例：缺当前附件 → `REQUEST_ASSET_MISMATCH`；过期请求 → `REQUEST_CONFLICT`；未检查的真实提取帧 → `CRITICAL_IMAGE_REVIEW_REQUIRED`。均在生成前拒绝。
- 实际生成：6 次完成，保留所有原始和修复输出。
- 实际合成：完成，技术检查无 issues，`finalReady=true`、`reviewAccepted=false`、`status=unreviewed`。
- 代码变更自查、类型检查及 `git diff --check` 通过。没有进行独立子代理审查。

## 预算

共 6 次视频生成，没有图片生成或额外付费视觉分析。实际使用测试计费路线，六次服务记录中的 `actualCostCents` 均为 0；这是用户侧服务账单，不能当成供应商推理完全免费。

为约束测试账户可能承担的上游费用，按 [fal 官方 H3 Max 参考视频计费](https://fal.ai/models/minimax/h3-max/reference-to-video) 保守计算：768P 输出 USD 0.08/秒；所有参考视频为 9:16、60fps、最长 3.7 秒（至多 222 帧），用官方 240 帧对应的 67,536 参考 token 上界；产品图按允许图形比例的最高 2,560 token 计；扣除每次 4,096 token 免费额，再按 USD 0.02/千 token 计。

- 每次 4 秒调用上界为 USD 1.64，共 5 次。
- 一次 5 秒调用上界为 USD 1.72。
- 合计保守预算占用 **USD 9.92 ≤ USD 10**。供应商最终发票没有取得，9.92 不是实际扣款声明。
- 保留初始预留、重新核价依据、稳定幂等键和六次任务 ID；预算账本已标记停止生成，没有继续重试。
