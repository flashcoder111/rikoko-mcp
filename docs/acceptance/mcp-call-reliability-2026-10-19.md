# MCP 调用可靠性补充（2026-10-19）

## 已实现

- HTTP/MCP 统一返回 error.code、message、traceId、details、recovery；MCP 错误文本同时包含完整 JSON，兼容 Hermes 对 isError 的文本转发。HTTP → stdio 桥接保留 traceId。SDK 进入回调前的参数校验仍使用 SDK 原生格式。
- 保留嵌套字段路径；计划校验失败附带结构化问题列表；计划保存和提示词读取的版本冲突返回当前已授权记录的版本与 ID。
- `media_inspect` 区分缺失 FFmpeg、源文件缺失、权限、磁盘空间、抽帧输出缺失、处理失败和超时。诊断包含失败阶段及有限的退出信息；已知 stderr 特征转为固定原因标签，不透传原始 stderr、命令、私有路径或 URL。临时文件清理失败不覆盖原始处理结果。
- 新增 `media_runtime_check`，通过后端实际 FFmpeg 路径执行合成图像抽帧、缩放、PNG 和灰度解码。并发自检共享一次执行，不持久化资产、不调用模型。
- `pnpm clients doctor hermes --media` 检查已安装配置对应后端，失败返回非零退出码，不再把连接成功当成媒体就绪。
- 后端缺少桥接端公布的工具时返回 `BACKEND_TOOL_UNAVAILABLE`；网络失败及成功响应无法解析时明确提示写操作结果可能未知，不自动重放。
- Hermes 指引明确区分结构化元数据与 JSON + MEDIA 的展示文本；补充版本恢复、冷却等待、禁止相同参数循环重试和禁止重复生成的流程。

## 第一阶段结束时的本机现状与限制（启用前）

本次只完成当前 main 分支上的本地修改，保留已有工作区改动。未创建分支、未提交/推送、未部署、未重启后端或 Hermes、未同步修改已安装的 Skill、未执行付费任务。使修改生效需要将这一版本加载到对应后端与 MCP 桥接端，再重载 Hermes 连接；仅重载桥接端不能更新旧后端。

未对用户截图对应的原 assetId 重新执行检查，也未做真实聊天中的像素可见性或附件投递验收。因此这些改动改善故障定位与恢复，不构成对未知原始媒体故障的修复证明。
