# Hermes 参考分析协议修复验收（2026-10-17）

## 已确认的故障

Hermes 会话 `20261017_154509_8f15a7` 的三次 `reference_analyze` 在进入模型前被拒绝。线上镜像 `video-workbench-cloud:20261015-speech-recovery` 使用 rikoko **0.1.12**、`reference-v2.1`；其严格输入校验不支持本地发送的 `detail`、`focus`。在原容器直接执行相同形状的输入校验，得到 `unrecognized_keys: [detail, focus]`。这不是 Gemini 对汉堡制作理解失败，也不是素材上传失败。

原会话后来跳过语义分析，仅将运动参考和临时提示词用于生成。制作状态不连续、输出时长截断和结尾占位画面是后续独立问题；恢复分析是修复链路的第一步。原视频、四个片段、项目及已生成素材均保留。

## 本次修改

- 共享运行时声明分析协议版本、支持的细节层级、关注项和报告版本。
- 云端模型目录返回实际运行时支持的协议；`/health` 显示运行时及分析版本。
- 客户端在上传和报价前验证云端协议。不兼容时明确返回 `ANALYSIS_PROTOCOL_MISMATCH`，不删除参数、不降级、不反复重试。未配置的模型仍单独返回 `CAPABILITY_UNAVAILABLE`。
- 云端输入错误附带版本信息，但不回显用户提交的无效字段值。
- MCP 与技能指导要求保留计划，暂停依赖失败分析的复刻。Hermes 已安装技能中“跳过 Gemini、默认中心裁剪”的错误规则已定点替换，原文件另行备份。
