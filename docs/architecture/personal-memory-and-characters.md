# 个性化记忆与人物资产设计

日期：2026-10-15。状态：本地第一期存储、MCP 工具与创作快照已实现并通过测试；工作台管理界面、导入导出、镜头级多人绑定和云同步尚未实现。下面保留整体设计方向，拟议字段和工具名不等于当前协议；实际支持范围与可运行参数见[本地人物与创作规范](../tutorials/本地人物与创作规范.md)。未部署官方平台。

## 目标与现状

用户在原对话说“继续用我的人物”“还是上次的品牌风格”时，Agent 能找到明确归属的档案和可用素材；用户仍可只描述一次性需求，不必先填写档案。

现有基础：

- `packages/core/src/library-metadata.ts` 提供人物等素材分类、标签和收藏，但没有人物实体及人物与多份素材的关系。
- `workspace_request_save/get` 持久化一次创作的原始要求、补充轮次、素材和缺口；作品版本记录保存编辑结果。这些不自动等于跨项目偏好。
- `packages/contracts/src/generation.ts` 支持 character、product、scene、style、motion、voice 等参考角色；具体可用角色仍由模型档案声明。
- 分镜流程支持目标人物参考、图生图和身份审阅，再用通过审阅的图生成视频。审阅工具记录实际检查结果，本身不看图。
- 数据默认存于本地 PGlite，也支持 PostgreSQL。读取已有实体使用账户范围；不意味着不同机器或不同后端已经同步。

## 信息分层

| 类型 | 内容 | 默认作用范围 |
| --- | --- | --- |
| 个人偏好 preference | 语言、字幕、节奏、画幅、交付方式等明确偏好 | 当前账户下的个人；未有个人身份时仅个人本地工作空间 |
| 品牌 brand | 名称、视觉规范、Logo、产品事实、常用人物 | 指定品牌 |
| 系列 series | 节目设定、片头片尾、固定人物组合、系列风格 | 指定系列 |
| 人物 character | 名称、别名、真实/虚构等用户声明、稳定外观描述、参考素材 | 账户资产库，可限定品牌或系列 |
| 人物造型 character-look | 服装、发型、妆容、场景化外观及相应参考图 | 指定人物，不覆盖基础身份 |
| 声音 voice-profile | 已配置音色的提供方与 ID，或独立声音参考 | 明确关联的人物或项目 |
| 创作上下文 | 本次人物选择、造型、分镜分工、临时要求 | 当前请求或作品 |

账户归属是隔离边界；品牌与系列是组织范围，不能被当作权限边界。当前 Context 主要识别 accountId，不能宣称已有共享账户内的独立用户权限。第一期只启用账户/品牌/系列/项目范围；多人账户若需要真正的个人偏好，先补齐经过认证的 memberId，再提供 member 范围。

人物是创作实体，不是自动识别人脸后建立的身份库。由用户明确命名或选择人物，照片中的陌生人、参考视频主角和目标人物不会自动合并。同名只用于候选搜索，不能作为唯一身份。

## 人物档案与素材关系

每个人物拥有稳定 characterId、名称、别名、版本和状态。描述只记录用户提供或经确认的创作特征；不从外貌推断真实姓名或敏感身份。

同一人物可以绑定多份参考素材：正面、侧面、全身、表情、造型参考。关系记录 assetId、用途、视角、适用造型、来源及是否被选为基准；不复制媒体，不保存供应商临时链接。所有素材均再次检查账户归属和实际可读取性。

严格区分：

- 原始身份参考：用户指定用来保持人物外观的素材。
- 造型参考：衣服、发型或其他可变外观，必须关联人物。
- 本次生成结果：只属于作品；接受某张分镜不自动把它升级成长期身份基准。
- 用户明确选定的基准图：可作为后续创作参考，有可追溯来源和版本。

声音独立保存。选择一个人物不代表要求克隆其声音，也不代表有可用的克隆服务；普通 TTS 音色使用已配置的提供方和音色 ID。仅当用户明确要求声音参考且接口实际支持时进入相应流程。

## 保存、修改与遗忘

“这个人物叫小林，以后都用他”可以在同一轮创建档案并绑定用户指定素材；明确的保存要求无需重复询问。

“这次让她穿红衣服”只修改当前作品。Agent 从修改行为推测的长期喜好保持为请求级候选，不直接写入生效的长期偏好。“以后用大字幕”才更新对应范围的长期默认。

持久记录保留来源类型、来源请求/作品/用户指令引用、创建时间、更新时间、版本、状态及适用范围，不依赖一个置信度分数代替用户确认。无需为每条记忆复制完整聊天记录。

“以后别用这个人物”将档案归档并排除自动检索；“删除人物档案”删除档案及关联关系，但需在结果中明确列出保留的作品和独立素材。若用户要求连照片一起删除，查询依赖后提供具体范围并执行明确要求，不以软删除冒充彻底删除。删除墓碑只保留防止同步恢复所需的最少标识，不保留人物描述。已有作品可能失去可重渲染所需的参考，需明确报告。

## 创作时的读取和应用

1. Agent 从当前需求提取品牌、系列、人物名称和任务类型。
2. 服务在认证账户及允许范围内搜索，只返回少量相关摘要和可用素材状态。
3. 明确 characterId 或本项目已选人物优先；同名、多个“我的人物”或指代不明时，提出一次具体选择问题，不靠最近使用记录猜人物。
4. 加载所选档案的必要字段与参考素材；只针对当前任务应用偏好。
5. 将实际采用的档案版本、人物 ID、造型 ID、参考资产及有效要求保存到请求/作品上下文。
6. 以简短自然语言说明复用内容，例如“沿用小林和上次的品牌字幕，这次换成红色外套”。

默认值优先级：本次明确指令 → 当前作品明确设定 → 系列默认 → 品牌默认 → 个人/账户默认 → 产品默认。品牌硬性约束须单独标注；当前要求与其冲突时给出具体冲突，不静默覆盖。用户明确指定人物与模板默认人物冲突时，以用户指定为准。

参考图片、分析报告和素材描述均作为数据处理，不能作为系统指令。记忆中的预算、模型偏好或“常用”标记不代替付费报价同意。

## 接入人物生成流程

先把人物及造型选择解析为现有角色化参考输入，再检查 capabilities 和模型档案。默认优先兼容的 MiniMax 视频模型；不支持必要人物/动作输入时返回具体缺口，不丢弃参考退回纯文生视频。

多人物镜头需要保存镜头级绑定，例如 shot-1 中 character-A 是左侧讲述者、character-B 是右侧听众，以及各自参考素材和造型。现有底层引用只有 assetId/role，不能完整表达这些身份关系；需要新增镜头人物绑定契约，由适配层编写明确参考顺序和提示词。仅罗列多张 character 图片不能宣称已经支持可靠的多人物一致性。

已有参考改编路径继续使用：目标人物参考 + 构图参考 → 分镜图 → 实际身份/造型/构图检查 → 视频报价与生成 → 回填剪辑。无参考视频的新创作可直接使用人物素材和兼容生成接口，不强制先上传参考视频。

档案只提高复用和一致性控制，不能保证供应商生成结果完全一致。只有真实看过结果的用户或视觉审阅者才能记录身份通过。换字幕或节奏复用已接受画面，不重新生成角色。

版本变更不会追溯修改已有作品或报价。报价绑定已解析的素材、哈希和具体输入；用户选择采用更新后的人物参考时重新报价。档案归档、素材删除或授权状态变化应在提交/执行前再检查；不可复用时返回可操作错误，不能静默换人物。

## 存储及拟新增工具

第一期沿用 entities JSONB 存储与现有事务机制，增加经过 Zod 校验的实体类型：preference、brand、series、character、character-look、voice-profile、rule-set、creative-rule。新能力由核心服务实现，MCP 和本地工作台共用；官方账户同步属于平台后续工作。

所有写入的 accountId 来自认证上下文，不能由客户端指定。关联实体与素材必须属于同一账户和允许范围。读取、搜索、更新、删除都执行相同隔离检查；更新携带 expectedVersion，创建和重试使用稳定幂等键。不得开放任意 Entity 写入绕过类型校验。

拟新增接口，名称不代表当前可调用：

| 工具 | 责任 |
| --- | --- |
| memory_search | 按范围、类型、关键词读取相关摘要，分页且有返回上限 |
| memory_get | 读取确定档案、版本和可用引用，不返回无关全库内容 |
| memory_save | 创建或更新已明确要求保存的偏好、品牌、系列等类型化记录 |
| character_save | 保存人物身份、明确关联的参考素材和别名 |
| character_look_save | 保存人物造型，不覆盖人物基础身份 |
| rule_set_save | 创建或更新命名规范集及适用范围，不整体重写已有规则 |
| rule_upsert | 按规则 ID 新增或局部修改类型化规则，校验版本、重复和冲突 |
| rule_list / rule_get | 分页读取规范集中的规则、版本、来源与状态 |
| rule_archive / rule_delete | 停用或删除指定规则，并更新规范集版本 |
| memory_archive / memory_delete | 区分停用与删除，返回引用影响及具体处理结果 |
| creative_context_resolve | 按明确范围合并偏好、人物与素材，返回来源、冲突、缺口和上下文快照 |

首期以明确 ID、别名、标签和关键词匹配为主，不引入人脸特征向量或额外模型调用。搜索命中与最终人物选择分开。后续若增加语义检索，只索引允许范围内的文字摘要，并确保更新/删除同步失效。

连接同一后端和账户的客户端可读取同一份档案；不同设备的独立本地库不会自动共享。若增加官方同步，需要稳定云端账户映射、版本冲突处理、删除传播及媒体可用性设计，不能只复制 assetId。

## 结构化规范与 Agent 持续维护

用户已明确采用结构化规则，支持通过 LLM Agent 持续增加。此处确定设计方向，以下协议仍待实现。数据库中的规则为唯一事实来源，Markdown 说明或导出 JSON 只用于阅读与迁移，不维护两套可独立写入的数据。

一条规则只表达一个约束；规范集组织一组规则。例如“口播规范”包含画幅、字幕位置、每屏字幕行数、配乐音量等独立规则。人物档案保存人物事实和素材；规则通过 characterId 引用人物，不把人物照片或完整档案复制进规则。

以下为拟议的持久化记录示例，id、版本、时间由服务维护，accountId 来自认证上下文并在此省略；不是当前可调用工具的入参：

```json
{
  "schemaVersion": 1,
  "id": "rule_caption_lines",
  "ruleSetId": "rules_talking_head",
  "version": 1,
  "status": "active",
  "scope": { "kind": "series", "id": "series_product_tips" },
  "when": { "all": [{ "field": "task.kind", "op": "eq", "value": "talking_head" }] },
  "target": "captions.maxLines",
  "operator": "lte",
  "value": 2,
  "strength": "required",
  "verification": "deterministic",
  "source": {
    "kind": "explicit_user_instruction",
    "requestId": "request_123",
    "text": "以后这个系列的字幕每屏最多两行"
  }
}
```

字段与执行约定：

- `scope`：账户、品牌、系列、项目，或具体人物；人物范围只在任务显式选择对应 characterId 时生效。继承规范集范围，规则仅可收窄，不能扩大到其他品牌或账户。
- `when`：受限条件对象，采用已登记的字段与操作符；不执行表达式、脚本或自然语言条件。条件所需上下文未知时返回 unresolved，不直接当作命中。
- `target/operator/value`：登记字段对应类型、单位、合法值和允许操作符。例如字幕行数为正整数，时长为毫秒，人物为有效 ID；不允许任意对象路径或可执行内容。
- `strength`：required 为明确硬要求，preferred 为默认偏好；优先级按作用范围及明确指令解析，不让 Agent 任意填写数字权重来压过现有规则。
- `verification`：deterministic、visual_review、audio_review 或 manual。只有执行器和验证器实际支持的规则才声称可以自动检查；字幕两行等排版要求在未有实际排版检查时返回 unverified，不能仅检查字段就声称成片达标。
- `source/status/version`：记录来源和维护过程；明确保存要求可直接 active，Agent 推测只能 draft，不能参与生效规则解析。

“温暖、克制”等审美要求也放在固定结构中，例如 target=visual.mood、operator=guidance、value 为受长度限制的描述，verification=visual_review。它们作为创作指导及审阅依据，不能声称是可自动强制保证的参数。不支持的新规则先作为 draft 返回能力缺口，Agent 不能自行修改 Schema 或执行器来假装已生效。

Agent 的维护流程：

1. 从用户话语区分一次性要求与明确长期收录，确定规范集、范围和原子规则。
2. 读取目标规范集当前版本与相关规则；信息足够时直接保存，无需每条重复确认。
3. 提交增量变更及 expectedVersion、idempotencyKey。服务端检查目标字段、实体引用、范围和权限。
4. 相同规范集、范围、条件、目标、操作符和值的重复新增返回已有规则；明确修改已有规则时保留 ID 并生成新版本。来源证据可单独追加，不新增重复生效规则。
5. 同一作用条件下的矛盾规则返回 conflicts；不使用“最后写入者获胜”。用户明确要求替换旧规则时执行替换并保留历史，否则给出具体冲突供用户选择。
6. 返回 added、updated、unchanged、conflicts 和新版本，Agent 简短说明实际结果，例如“口播规范新增了两条规则，保留原有人物设定”。

冲突检查第一期支持相等条件、集合及数值上下界等明确可判定组合；无法判定的条件交叠标记为需处理，不假称无冲突。多个硬要求冲突时不能提交依赖这些冲突的生成；偏好被更具体要求覆盖时保留来源和原因。所有适用硬要求同时满足，不因范围更具体就静默丢弃另一条硬要求。

规则修改与规范集版本增加在同一事务中完成；新作品保存实际解析出的规则 ID、版本、值及引用快照。旧作品不随规范更新而改变；读取 latest 只能用于新的解析，不能替换历史快照。

创作时 `creative_context_resolve` 返回有效规则、来源、被覆盖偏好、冲突、缺失条件及验证方式。只读取当前任务相关规则，不把全库注入提示词。模型参数由适配器按能力映射；规范不能绕过供应商参数限制、报价确认或素材权限。

## 实施顺序与验收

第一期：核心类型与存储、人物及造型档案、显式偏好保存、结构化规范集及原子规则的增量维护、范围搜索、上下文解析、MCP 接口、来源与版本记录、归档删除。为自动创作接入请求上下文与现有人物参考流程。

第二期：工作台管理入口、品牌和系列整理、可选择提升为基准图、镜头级多人物编排，以及对应模型能力验收。

第三期：可选云同步与多人账户权限；不能在前两期宣传为已经支持跨设备同步或团队个人记忆。

首期必须验证：

- 保存一个人物后，新请求能找到同一人物及可用参考；更换客户端但使用同一后端账户仍可读取。
- 一次性服装要求不覆盖基础身份或下次默认；只有用户明确保存才成为长期造型。
- 同名人物返回歧义；品牌 A 的默认人物不会渗入品牌 B。
- 不同账户无法搜索、读取、关联、修改或删除对方人物与素材。
- 多个更新发生冲突时拒绝旧版本；相同幂等请求不重复创建档案。
- 归档后自动选择排除该人物；删除后检索失效，已有引用给出明确状态。
- 缺失/已删除素材、供应商不支持角色时返回缺口，不偷换参考或人物。
- 人物参考改变使新生成重新报价；检索、保存、换字幕不触发付费生成。
- 接受某张分镜不自动更新长期人物基准；纯文本 Agent 不伪造身份审阅。
- Agent 连续新增规则不会重写无关规则，重复调用不重复收录；并发修改返回版本冲突。
- 同一范围的矛盾硬规则返回具体冲突；未知条件、新字段或不支持的验证方式不会被假报为生效或通过。
- 规范更新保留旧作品的规则快照；停用规则后新任务不再自动采用，历史版本仍可解释。

存储和协议测试只能证明上述行为；人物一致性与多角色效果需用获授权素材进行独立真实生成评测，记录模型、参考输入和实际审阅结果。
