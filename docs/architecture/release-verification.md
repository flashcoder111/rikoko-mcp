# 当前源码的发布验收

在维护仓库执行 `pnpm verify release --automated`。命令不发布、不部署、不创建 Git 分支、不使用真实模型凭据购买生成。它创建带时间戳的 `artifacts/release/<run>/`，保留公开源码快照、逐步日志、机器可读报告和人工证据模板。

自动检查依次执行：公开导出与有限凭据模式检查、指南/类型/前端构建、完整 TypeScript 回归、Python/FFmpeg 媒体测试、安装器语法、隔离安装与真实 stdio 接入、重复安装、实际升级，以及候选启动后失败时的程序/数据回退。最后再次导出源码；检查期间源码变化会使本轮失败。源码指纹同时绑定导出内容和发布检查脚本。

安装验收只使用临时目录与临时 Codex/Claude Code 配置；归档下载使用受控传输替身，依赖来自已有缓存，Node/uv/FFmpeg 使用当前机器安装。生成请求为零。它不等于全新系统引导、厂商客户端 UI 操作或真实模型质量验证。报告中的平台仅表示本次实际运行的平台，不能外推 Linux、WSL 或其他架构。

## 正式门槛

默认 `pnpm verify release` 不会仅凭自动检查就判定正式通过。选择发布范围：

- `--scope local`（默认）：已有素材编辑、模板、本地渲染、MCP 交付。需要干净机器安装、真实宿主完整流程与发行许可核对记录。
- `--scope generation`：额外要求对公开支持的每个模型/接口完成真实调用、质量与费用核对。模型偏好不是预算授权；未完成的音频、克隆、严格复刻等能力应标为实验或从承诺范围排除。

每项证据应记录日期、操作人或测试执行者、系统/架构、客户端版本、步骤、实际结果与限制：

| ID | 验收内容 |
| --- | --- |
| `clean-machine-install` | 宣布支持的系统与架构；无预装依赖引导、首次安装、旧版升级、任务未结束时拒绝升级、失败回退 |
| `host-user-journey` | 宣布支持的每个宿主：导入、创作、续改、附件/链接交付、关闭重启恢复；确认用户能看到并播放结果 |
| `license-review` | 对本次发行内容核对 LICENSE、第三方依赖/字体/媒体来源及分发范围；有限模式扫描不等于许可批准或完整秘密扫描 |
| `provider-live` | 生成版支持的模型与模式、配置及已确认费用上限；真实输出、超时/取消/重连、计费记录、人脸限制；生成成功不等于严格复刻通过 |

复制本轮生成的 `evidence-template.json` 到自己的验收目录。只将实际完成的项目设为 `PASS`，填写相对于仓库的证据文件路径与该文件 SHA-256，保留准确的 `sourceSha256` 和 `scope`，然后执行：

```sh
pnpm verify release --scope local --evidence artifacts/acceptance/release-evidence.json
```

所有自动检查都会重新运行；源码不同、证据文件缺失/变化、重复 ID 或未完成项目不会通过。证据哈希校验确认记录对应关系，不代替对记录内容的人工判断。

退出码：`0` 表示所选门槛通过（`--automated` 仅代表自动门槛）；`1` 表示自动检查失败；`2` 表示自动检查通过但正式验收缺项。报告同时输出 `automatedPassed` 与 `releaseReady`，不可混用。CI 使用 `--automated`，上传报告与日志，不会因此自动发布。

## 当前能力承诺

默认视频选择与人脸限制已有源码及自动回归。Seedance Mini 的发行示例费用上限尚未确认，保持禁用是预期保护，不能当作开箱即可购买。正式支持该模型前，需要实际账户配置和授权试生证据。复杂参考视频的动作/时序保真与声音生成听感也需要真实输出验收，不能用参数、分辨率或单元测试替代。

安装器升级只支持其托管的本地 PGlite 实例。云平台账户、充值与结算属于 rikoko-platform，不包含在本仓库的本地发布门槛内。
