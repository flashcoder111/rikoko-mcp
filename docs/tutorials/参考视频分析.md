# 独立参考视频分析

rikoko 的视频分析服务独立于 Hermes、Claude Code、Codex 等宿主的对话模型。宿主使用纯文本模型时，也可以通过 MCP 获取参考视频的镜头、动作、叙事、画面文字、语音、声音证据和待确认项，再生成可编辑分镜。视频生成仍优先采用已配置的 MiniMax。

## 当前实现与边界

- 自定义供应商模式新增 `gemini` 适配器：Google Files API 上传本地私有视频，Interactions API 后台分析同步音视频，不依赖公开下载链接或 S3。
- FFmpeg 测量候选画面切点；模型给出的镜头和事件时间标记为估计值。切点候选不等于真实镜头边界。
- `ReferenceAnalysis v2` 保存源素材 ID、SHA-256、时间基准、供应商请求 ID、模型配置、采样设置、结构化证据与覆盖缺口。
- 已知请求可继续查询、取消或恢复；无法确认是否受理的请求进入人工核对状态，不自动重新购买。
- MCP 默认返回简洁概要，明细支持分页；改编使用实际分析出的镜头长度和镜头对应关系。
- 官方套餐的分析上传与计费接口仍需由 `rikoko-platform` 接入。当前实现不把个人 Gemini 支出计入官方套餐，也不会从官方模式自动切换支付来源。

本版本使用可配置的静态视频采样。Gemini 的视频接口同样可能漏掉快速动作；接收完整视频不等于逐帧无遗漏。高密度复查需选择单独配置的档案并重新报价。[Google 视频理解说明](https://ai.google.dev/gemini-api/docs/video-understanding)

本版本没有自动运行 ASR 强制对齐、节拍/BPM 检测或 Pegasus，也没有实测模型准确率。语音内容来自音视频模型，不能冒充逐词对齐结果。无音轨的源视频不允许报告语音或声音证据。

## 配置

在运行本地服务和 Worker 的环境中设置 `GEMINI_VIDEO_API_KEY`，不要把 Key 放入 MCP 参数、聊天内容或提交到仓库。参考 `config/models.custom.example.json` 中的 `my-video-analysis`，将它合并到现有自定义配置，保留已有生成模型连接。兼容环境变量 `HYPIT_CONFIG_FILE` 指向该配置文件。

示例包含两个分析档案：

| ID | 采样设置 | 用途 |
| --- | --- | --- |
| `gemini-reference` | 2 FPS，源片不超过 60 秒，输出最多 8192 tokens | 整体结构拆解 |
| `gemini-reference-detail` | 8 FPS，其余限制相同 | 已定位的动作、转场或画面文字区间 |

示例的 `maxCostCents` 是待核对占位值，**不是供应商报价**。核对供应商模型权限、输入/输出与思考 token 计费、最大视频时长/采样率及安全余量后，填写自己的费用上界与 `priceVersion`，再设置 `hardBoundConfirmed: true`、`enabled: true`。修改连接、密钥或费用档案后，旧任务不会静默迁移到新连接；需恢复原配置查询。

时长上限约束整个上传文件，即使只分析其中一个区间。更长的视频先通过本地 `trim` 分段，或配置经过费用核对的更长档案；最高支持 10 分钟、100 MiB。服务器拒绝未经报价的调用方采样参数覆盖。此处限制用于约束请求，供应商真实费用仍需对账。

上传视频进入 Google Files 服务；本版本不主动删除远端文件，应按供应商文件保留规则管理数据。后台 Interaction 以 `store: true` 保存，以支持恢复查询。[Files 文档](https://ai.google.dev/gemini-api/docs/files)、[Interactions API](https://ai.google.dev/api/interactions-api)

## 一次完整调用

1. 用现有素材导入工具导入有权使用的视频，取得 `assetId`。调用 `capabilities` 确认分析档案可用。
2. 调用 `reference_analyze`：

   ```json
   { "assetId": "SOURCE_ASSET_ID", "model": "gemini-reference", "purpose": "remake", "language": "zh" }
   ```

   返回已缓存结果、现有任务，或 `quote_required`（含 `quote` 与规范化后的 `input`）。此步骤不会上传视频或调用付费模型。

3. 用户同意该报价后，将**原样返回的 `input`**、`quote.id` 和稳定的 `idempotencyKey` 传给 `job_submit`。用 `record_get(type="job")` 查询状态，不要重新提交来查询进度。更换幂等键属于新购买。
4. 完成任务的 `outputs[0]` 是分析资产 ID。调用 `reference_analysis_get({analysisAssetId})` 获取概要；传 `section: "shots" / "events" / "evidence" / "narrativeBeats" / "speech" / "unknowns"`、`offset`、`limit` 分页读取。只有明确需要完整 JSON 时使用 `section: "all"`。
5. 调用 `reference_adapt`，用 `sourceShotId` 指定自己的文案和素材：

   ```json
   {
     "analysisAssetId": "ANALYSIS_ASSET_ID",
     "title": "我们的产品视频",
     "replacements": [
       { "sourceShotId": "shot1", "text": "我们的开场", "assetId": "OWNED_IMAGE_ID" },
       { "sourceShotId": "shot2", "text": "产品展示" }
     ]
   }
   ```

   返回 `composition`、`shotMapping`、`generationRequired` 和待确认项。未提供媒体的镜头是待补素材的分镜卡；不会自动生成，也不会自动复制原片。明确允许引用原片画面时传 `reuseReference: true`。该工具按镜头映射和替换参数建立分镜，不会额外调用文字模型创作营销文案。
6. 审阅分镜后，把 `composition` 传给 `workspace_commit`；缺失素材可单独报价并采用 MiniMax 等已配置生成接口补齐。传入 `projectId` 时，`reference_adapt` 也可先保存编辑版本而不渲染。

`plan_create` 收到 v2 分析资产时，同样使用分析出的镜头结构，不再采用固定三段模板。需要逐镜头替换时直接使用 `reference_adapt`。

## 定向复查

`reference_analysis_query` 按原片时间范围检索已有证据，例如：

```json
{ "analysisAssetId": "ANALYSIS_ASSET_ID", "startMs": 8000, "endMs": 11000, "question": "这个转场的动作顺序是什么？" }
```

返回值明确标记 `retrievalOnly: true`；它不会凭摘要生成新答案。需要复查时，使用返回的 `refinementInput` 重新报价，必要时将模型换成 `gemini-reference-detail`。只有新报价获同意后才提交。局部复查保存为独立报告，不覆盖整体结果，时间保持原片绝对毫秒。当前不自动合并报告或自动购买第二轮分析。

## 结果可信度和恢复

`source` 和 `provenance` 由服务端绑定，不接受模型伪造。服务端检查时间越界、镜头重叠、重复 ID、无效证据引用及无音轨情况下的声音幻觉。`coverage` 表示请求区间、采样策略和镜头时间缺口，不能解释成每帧都已检查。`confidence` 是模型自报等级，不是校准后的准确率。

上传处理中的文件句柄、已受理的分析请求 ID、分析结果均进入任务检查点。`failed` 且保留已知票据的任务可用 `job_resume` 继续取回原请求结果；`submission_unknown` 必须先核对供应商记录。取消会请求供应商停止原任务，但不承诺退款。

费用上界用于报价和预算占用。分析结果不会把报价上界填成真实供应商费用；完成后费用保持 `pending_reconciliation`，直到有可靠供应商账单证据并完成对账。缓存只在同一账户、同一输入、同一模型/连接/分析版本下命中；显式 `refresh: true` 会重新报价。

## 本地验收

`tests/reference-analysis.test.ts` 覆盖独立分析、证据校验、分页、任务恢复、缓存、引用权限、分镜映射和真实 FFmpeg 渲染。`tests/gemini-analysis.test.ts` 覆盖官方请求格式、秒/毫秒转换、文件上传轮询、连接变化、费用边界与上传 URL 凭据隔离。

供应商响应均为可控模拟；真实视频仅用于本地切点与渲染验收。上述测试通过不能等同于真实 Gemini 接通、付费效果验收或生产部署。
