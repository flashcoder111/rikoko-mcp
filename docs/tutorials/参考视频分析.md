# 独立参考视频分析

rikoko 的视频分析服务独立于 Hermes、Claude Code、Codex 等宿主的对话模型。宿主使用纯文本模型时，也可以通过 MCP 获取参考视频的镜头、动作、叙事、画面文字、语音、声音证据和待确认项，再生成可编辑分镜。视频生成仍优先采用已配置的 MiniMax。

## 当前实现与边界

- 默认示例使用 `fal-video` 适配器：本地视频上传 fal CDN，经 `openrouter/router/video` 选择 `google/gemini-3.8-flash`。只需 fal Key，无需 Google 或 OpenRouter Key。保留可选的 `gemini` 原生适配器。
- FFmpeg 测量候选画面切点；模型给出的镜头和事件时间标记为估计值。切点候选不等于真实镜头边界。
- `ReferenceAnalysis v2` 保存源素材 ID、SHA-256、时间基准、供应商请求 ID、模型配置、采样设置、结构化证据与覆盖缺口。
- 已知请求可继续查询、取消或恢复；无法确认是否受理的请求进入人工核对状态，不自动重新购买。
- MCP 默认返回简洁概要，明细支持分页；改编使用实际分析出的镜头长度和镜头对应关系。
- 官方模式通过 `rikoko-platform` 网关上传、报价和获取分析报告；是否可用以 `capabilities` 的当前模型与连接状态为准。个人 fal/Gemini 支出与官方套餐分开，不自动切换支付来源。

fal 的视频接口接收完整视频 URL，没有公开 FPS、API 裁剪或 JSON Schema 参数。因此 fal 分析结果记录 `fps: null`、`mode: "provider_controlled"`、`rangeControl: "prompt"`，不会冒充 2/8 FPS 或逐帧精度。结构化输出通过提示词指定 JSON Schema，并在本地严格校验；无效结果直接报错，不自动付费重试。[fal 官方视频接口](https://fal.ai/models/openrouter/router/video/api)

本版本没有自动运行 ASR 强制对齐、节拍/BPM 检测或 Pegasus，也没有实测模型准确率。语音内容来自音视频模型，不能冒充逐词对齐结果。无音轨的源视频不允许报告语音或声音证据。

## 用自然语言调节精细程度

| 档位 | 用户说法 | 分析内容 |
| --- | --- | --- |
| `overview` 概览 | “快速介绍内容和风格” | 故事、主要段落、画面与声音风格；不要求完整镜头清单 |
| `shots` 逐镜头（默认） | “逐镜头分析，保留短镜头” | 独立剪辑镜头、主体外观、构图、环境、动作与转场 |
| `recreate` 复刻 | “用于后续生成，详细展开动作” | 完整镜头记录，以及起始/结束状态、空间关系、光线、分阶段动作、人物与相机运动、前后衔接 |

也可以直接用指令切换（中英文参数均可）：

```text
/rikoko analysis             # 查看当前设置
/rikoko analysis 概览        # overview
/rikoko analysis 逐镜头      # shots
/rikoko analysis 复刻        # recreate
/rikoko analysis auto        # 恢复自动选择
```

工作台输入框使用 `/analysis`，例如 `/analysis recreate`。指令通过 `reference_analysis_settings` 读取或保存当前账号的默认值，Agent 与工作台共用，重新打开后仍保留。单独切换只更新偏好，不上传素材、不创建报价或分析任务，也不会修改已有计划或报价。参数错误会显示合法选项，草稿和附件保留。

优先级为：本次明确指定的 `detail` → 账号保存的档位 → 自动推断。`auto` 时，`purpose: "remake"` 选择 `recreate`，其他用途选择 `shots`。没有单次覆盖时，Agent 应省略 plan/analyze 的 `detail`，由服务端应用保存的偏好；准备好的片段则沿用计划中已确定的档位。`focus` 可指定 `motion`、`camera`、`appearance`、`text`、`audio`、`continuity`。例如：“用复刻档分析这个视频，重点是动作与镜头运动，保留所有短镜头；第 5 镜写清起跳前、腾空中和切走时的状态。”宿主 Agent 根据这些要求设置工具参数，用户无需记命令。

复刻报告的每个镜头必须包含 `details`：`startState`、`endState`、`spatialRelations`、`lighting`、`actionStages`、`continuity`。每个动作阶段分别记录动作、主体运动和相机运动。静态镜头可以没有动作阶段；复杂动作按可见阶段展开，不靠最低字数凑长。未出现的接触、落地或结果不能补写成观察事实。旧 v2 报告仍可读取；新复刻任务缺少这些字段会报错，不会被当成完成。

这些档位同时控制输入拆分与输出结构，不是供应商的 FPS 参数。概览不用于直接建立生产分镜；图片提示词读取镜头初态和构图，视频提示词读取完整动作过程与终态，并保留邻镜状态作为衔接背景。完整记录始终保存在分析资产中。超过生成提示词长度限制时，要求 Agent 编写有取舍的独立提示词，不静默截断动作。

## 为完整逐镜头分析准备真实片段

逐镜头和复刻任务使用以下本地编排流程。`reference_analyze` 本身仍只报价一个输入，不自动购买整个计划。

1. 调用 `reference_analysis_plan`，传入 `assetId`、当前可用的分析 `model`、`detail`、`focus` 和可选的原片 `range`。工具测量候选切点并返回全部 `segments` 与 `estimatedCalls`，不调用供应商。计划可以用 `record_get(type="analysis-plan")` 恢复。
2. 调用 `reference_analysis_prepare({planId, offset: 0, limit: 4})`，依照 `nextOffset` 读完全部页。工具生成真实视频片段和代表帧，返回每段的原片范围及精确分析 `input`。重复准备复用已保存素材。准备好的片段直接报价，不再递归分片。
3. 对各段返回的输入调用 `reference_analyze`，汇总这批任务的报价与调用数；在已有授权范围内提交，或对整批取得一次价格同意。报价阶段官方模式可能上传素材；本地计划和切片不会上传。保持相同输入和幂等键，查询进度使用已有任务，不能为轮询重复购买。
4. 所有段完成后，调用 `reference_analysis_merge({planId, analysisAssetIds: [...]})`。工具要求每段恰好有一个匹配报告，把片段时间转回原片绝对毫秒，重映射证据 ID，并保留每镜全部动作、风格以及分段摘要和音频描述。不齐全或档位不符时报错，不静默丢段。
5. 用 `reference_analysis_get(section="shots")` 分页读取完整镜头，再进入分镜和生成流程；分段摘要、音频与来源通过 `section="parts"` 按需分页读取，避免重复挤占上下文。聊天概要是展示结果，不作为生成提示词的唯一来源。

本地规划目前最多接受 100 MiB 源片、100 个处理片段；每次准备最多 4 段。概览在 60 秒内可使用整片；逐镜头模式以不超过 12 秒、最多四个候选切点组织输入；复刻模式逐个候选切点拆分，连续长镜头再按不超过 8 秒的窗口处理。供应商文件、时长和报价限制仍独立适用。超过限制时缩小计划范围，不截掉尾部镜头。

候选切点不是已确认的剪辑边界，处理窗口也不等于新镜头。合并报告在 `analysis.parts[].boundary` 保存 `start/cut_candidate/window`；合并返回 `reportUnit` 和 `windowBoundaryCount`，有窗口时按镜头片段理解数量。当前不会凭时间相邻自动把片段判断为同一镜头。编码尾部的少量填充按显式 `timeMapping` 裁回原片范围；实际观察的时间缺口仍在 `coverage.gaps` 中保留。

## 配置

在运行本地服务和 Worker 的环境中设置 `MY_FAL_KEY`，不要把 Key 放入 MCP 参数、聊天内容或提交到仓库。参考 `config/models.custom.example.json` 中的 `my-video-analysis`，将它合并到现有自定义配置，保留已有生成模型连接。用环境变量 `RIKOKO_CONFIG_FILE` 指向该配置文件。

- adapter：`fal-video`
- 分析模型 ID：`gemini-reference`
- fal 端点：`openrouter/router/video`
- 上游模型：`parameters.model = "google/gemini-3.8-flash"`
- 示例范围：源片不超过 60 秒、80 MiB，输出最多 8192 tokens。

`my-video-analysis` 可与原有 `my-fal` 连接共用 `MY_FAL_KEY`；如果已有环境变量叫 `FAL_KEY`，将 `keyEnv` 改为该名字即可。fal 的 Gemini TTS 端点用于生成语音，不作为本分析接口。

示例的 `maxCostCents` 是待核对占位值，**不是供应商报价**。核对供应商模型权限、输入/输出与思考 token 计费、最大视频时长/采样率及安全余量后，填写自己的费用上界与 `priceVersion`，再设置 `hardBoundConfirmed: true`、`enabled: true`。修改连接、密钥或费用档案后，旧任务不会静默迁移到新连接；需恢复原配置查询。

时长上限约束实际上传文件；单独给 `reference_analyze` 设置 `range` 不会缩短 fal 上传。更长的视频先使用上述计划/准备工具生成真实片段，或配置经过费用核对的更长档案；fal 适配器最高支持 10 分钟、80 MiB。服务器拒绝未经报价的调用方采样参数覆盖。此处限制用于约束请求，供应商真实费用仍需对账。

上传视频进入 fal CDN，再通过其 OpenRouter 视频路由处理。CDN 地址可被持有链接者访问，不能当作私有鉴权 URL。本适配器请求 24 小时对象保留期，只持久化素材 URL，签名上传 URL 不进入任务记录；不承诺供应商已完成删除。上传文件的 PUT 请求不携带 fal Key，下载/上传 URL 限定到 fal 媒体域并禁用重定向。[fal 文件存储](https://fal.ai/docs/documentation/model-apis/fal-cdn)

## 单次分析与后续分镜

1. 用现有素材导入工具导入有权使用的视频，取得 `assetId`。调用 `capabilities` 确认分析档案可用。
2. 调用 `reference_analyze`：

   ```json
   { "assetId": "SOURCE_ASSET_ID", "model": "gemini-reference", "detail": "shots", "language": "zh" }
   ```

   返回已缓存结果、现有任务，或 `quote_required`（含 `quote` 与规范化后的 `input`）。此步骤不会提交付费分析；官方网关报价可能先上传源素材，个人适配器在执行任务时上传。

3. 用户同意该报价后，将**原样返回的 `input`**、`quote.id` 和稳定的 `idempotencyKey` 传给 `job_submit`。用 `record_get(type="job")` 查询状态，不要重新提交来查询进度。更换幂等键属于新购买。
4. 完成任务的 `outputs[0]` 是分析资产 ID。调用 `reference_analysis_get({analysisAssetId})` 获取概要；传 `section: "shots" / "events" / "evidence" / "narrativeBeats" / "speech" / "unknowns" / "parts"`、`offset`、`limit` 分页读取。只有明确需要完整 JSON 时使用 `section: "all"`。
5. 调用 `reference_adapt`，用 `sourceShotId` 指定自己的文案和素材：

   ```json
   {
     "analysisAssetId": "ANALYSIS_ASSET_ID",
     "title": "我们的产品视频",
     "replacements": [
       { "sourceShotId": "shot1", "text": "我们的开场", "assetId": "OWNED_IMAGE_ID" },
       { "sourceShotId": "shot2", "text": "产品展示" }
     ]
   }
   ```

   返回 `composition`、`shotMapping`、`generationRequired` 和待确认项。未提供媒体的镜头是待补素材的分镜卡；不会自动生成，也不会自动复制原片。明确允许引用原片画面时传 `reuseReference: true`。该工具按镜头映射和替换参数建立分镜，不会额外调用文字模型创作营销文案。
6. 缺失素材优先走 [参考图驱动生成](参考图驱动生成.md)：`reference_storyboard_prepare` 抽取真实构图帧和可选动作片段 → 图生图报价与生成 → `reference_storyboard_review` 记录视觉检查 → MiniMax 视频报价与生成 → 将生成素材填回 `reference_adapt.replacements`。审阅分镜后，把 `composition` 传给 `workspace_commit`。传入 `projectId` 时，`reference_adapt` 也可先保存编辑版本而不渲染。

`plan_create` 收到 v2 分析资产时，同样使用分析出的镜头结构，不再采用固定三段模板。需要逐镜头替换时直接使用 `reference_adapt`。

## 定向复查

`reference_analysis_query` 按原片时间范围检索已有证据，例如：

```json
{ "analysisAssetId": "ANALYSIS_ASSET_ID", "startMs": 8000, "endMs": 11000, "question": "这个转场的动作顺序是什么？" }
```

返回值明确标记 `retrievalOnly: true`；它检索已有记录，不产生新的视觉分析。返回的 `refinementInput` 保留报告档位和关注维度。对于“第 5 镜动作展开”，读取该镜原片范围，再用该 `range` 创建 `detail: "recreate"` 的新计划并准备真实片段，沿用上述报价、提交和合并流程。原报告保留，局部合并报告使用原片绝对毫秒。

直接使用 `reference_analyze.range` 时，fal 仍上传完整源片并通过提示词关注区间，不能声称减少了上传时长、费用或提高 FPS。只有准备得到的新片段才物理缩短输入。没有任何工具会自动购买第二轮分析。

## 结果可信度和恢复

`source` 和 `provenance` 由服务端绑定，不接受模型伪造。服务端检查时间越界、镜头重叠、重复 ID、无效证据引用及无音轨情况下的声音幻觉。`coverage` 表示请求区间、采样策略和镜头时间缺口，不能解释成每帧都已检查。`confidence` 是模型自报等级，不是校准后的准确率。

上传后的素材 URL、已受理的 fal 请求 ID、分析结果均进入任务检查点。`failed` 且保留已知票据的任务可用 `job_resume` 继续取回原请求结果；`submission_unknown` 必须先核对供应商记录。取消会请求供应商停止原任务，但不承诺退款。

`job.providerUsage` 保存接口实际返回的 `prompt_tokens`、`completion_tokens`、`total_tokens` 和原始 `cost`，不保存上游响应中的任意额外字段。该 `cost` 尚未作为已核实单位的结算值转换为整数美元分。费用上界用于报价和预算占用。分析结果不会把报价上界填成真实供应商费用；完成后费用保持 `pending_reconciliation`，直到有可靠供应商账单证据并完成对账。缓存只在同一账户、同一输入、同一模型/连接/分析版本下命中；显式 `refresh: true` 会重新报价。

## 本地验收

`tests/reference-analysis.test.ts` 覆盖独立分析、证据校验、分页、任务恢复、缓存、引用权限、分镜映射和真实 FFmpeg 渲染。`tests/fal-video-analysis.test.ts` 覆盖 fal 上传、模型锁定、实际请求字段、凭据隔离、Token 用量保存和任务恢复。原生 Google 适配器由 `tests/gemini-analysis.test.ts` 回归覆盖。

`tests/reference-detail.test.ts`、`tests/reference-planning.test.ts` 和 `tests/cloud-analysis.test.ts` 进一步覆盖精度档位、真实切片、完整合并、时间映射、详细提示词传递以及拒绝云端降档。自动化供应商响应为可控模拟；完整镜头召回率仍需要供应商实测。见 [本次精度优化验收](../acceptance/analysis-precision-2026-10-16.md)。本地代码通过不代表已部署到官方网关或已更新正在连接的 MCP 服务。

## 可选的 Google 原生接口

已有 `adapter: "gemini"` 的配置保持兼容，使用 Google Key、Files 和 Interactions API。它支持经报价固定的 FPS 与 API 片段范围；其参数档案与 fal 不可混用。新示例已按用户选择改为 fal，不会在 fal 失败后自动切回 Google 原生接口。
