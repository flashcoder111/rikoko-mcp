# 本地人物档案与结构化创作规范

已实现 HTTP/MCP 接口及本地持久化。用户通过已连接 rikoko 的 LLM Agent 使用，无需自己编辑 JSON。重启使用当前源码的后端并重载 MCP 后，新工具才会出现在已有客户端中。

可以直接说：

> 将这几张已上传的图片收录为“小林”的人物参考。
>
> 建立“口播规范”：以后竖屏 9:16，字幕最多两行，整体风格自然。
>
> 把“口播规范”的字幕改为最多一行，其他要求保持原样。
>
> 继续用小林，按口播规范制作新视频。

## 本地保存与维护

默认数据库在 `.data/db`（可由 DATA_DIR 修改），图片仍在原素材存储中。配置 DATABASE_URL 时使用对应 PostgreSQL；不会自动同步至官方云或另一台电脑。

- `memory_save`：保存人物、独立造型、品牌、系列和已经配置的音色档案。`kind` 分别为 character、character-look、brand、series、voice-profile。
- `memory_search/get`：按名称、别名检索后读取稳定 ID。遇到同名人物应消除歧义。
- `rule_set_save`：创建命名规范集，指定 account、brand、series、character 或 project 范围。
- `rule_upsert`：逐条增加或更新规则；未提供的字段保持不变。
- `rule_list` / `memory_history`：分页查看规则及历史版本。
- `memory_archive/delete`：停用或删除指定记录。停用不改变旧作品；删除会移除该记录、其编辑历史和修改缓存，但保留独立素材、已解析的规范快照及作品版本。依赖记录需要先解除引用，不会级联删除人物照片。

新增与修改均需要稳定 `idempotencyKey`；修改还需要当前 `expectedVersion`。重复调用返回同一结果，旧版本修改被拒绝。人物 `data` 按字段合并，数组整体替换，`null` 清除可选字段；必填字段不能清除。名称不能作为唯一 ID。

用户明确要求收录时填写 `source.kind=user_instruction` 和真实的指令摘要。Agent 推测使用 agent_inference，只能保存 draft，不参与创作。已有草稿经用户明确要求后可更新为 active。来源是可追溯记录，不等于独立证明或身份认证。

## 创建规范集与原子规则

以下是 MCP/HTTP 工具参数示例；将占位 ID 换成实际返回的 ID。

`rule_set_save`：

```json
{
  "name": "口播规范",
  "scope": { "kind": "account" },
  "source": { "kind": "user_instruction", "text": "以后口播按这套规范制作" },
  "idempotencyKey": "create-talking-head-rules"
}
```

`rule_upsert`：

```json
{
  "ruleSetId": "returned-rule-set-id",
  "when": { "taskKind": "talking_head" },
  "definition": {
    "target": "captions.maxLines",
    "operator": "lte",
    "value": 2
  },
  "strength": "required",
  "source": { "kind": "user_instruction", "text": "以后口播字幕每屏最多两行" },
  "idempotencyKey": "add-caption-lines"
}
```

`when` 当前只支持 taskKind、language 的精确匹配，多个字段同时满足才生效；缺少所需上下文会返回 unresolved。第一版 scope 由规范集决定，已有规范集不能直接迁移范围。

| target | operator / value | 验证方式 |
| --- | --- | --- |
| output.aspectRatio | eq / 9:16、16:9、1:1、4:5 | 对 composition 画幅自动检查 |
| output.durationMs | eq、lte、gte / 毫秒 | 对 composition 总时长自动检查 |
| editing.shotDurationMs | eq、lte、gte / 毫秒 | 对各镜头时长自动检查 |
| output.language | eq / 语言代码 | 只检查 composition.language 声明，不检测真实语音语言 |
| captions.maxLines | eq、lte / 1–10 | 视觉审阅，不把换行符数量当作最终排版行数 |
| visual.mood | guidance / 描述 | 视觉审阅 |
| character.identity | eq / character ID | 人物参考与视觉审阅，不自动识别人脸 |
| audio.voiceProfile | eq / voice-profile ID | 声音审阅，档案不保证提供方音色已可用 |

required 为硬要求，preferred 为偏好。同一规范集中的矛盾硬规则在保存时拒绝，跨规范集冲突在解析时返回。偏好按项目、人物、系列、品牌、账户的具体程度覆盖；同等范围的矛盾偏好不会按写入时间猜选。guidance 的审美描述不做自动语义矛盾检测。

## 人物与造型

`memory_save` 创建人物：

```json
{
  "kind": "character",
  "name": "小林",
  "data": {
    "aliases": ["主持人"],
    "description": "用户指定的固定人物",
    "referenceAssetIds": ["owned-image-id"]
  },
  "source": { "kind": "user_instruction", "text": "把这张图收录为小林的人物参考" },
  "idempotencyKey": "save-character-xiaolin"
}
```

造型另存为 character-look，data 包含 characterId、description、referenceAssetIds。人物可以限定 brandId 或 seriesId；使用时必须提供相符范围。声音档案保存 provider、voiceId 及可选 characterId，不执行声音克隆。

人物参考只接受本账户的已登记图片。用户接受某个生成结果，不会自动将它替换为人物基准。多个人物可以被明确选择，但第一版尚未增加镜头级人物站位、动作绑定契约。

## 将规则用于创作

1. Agent 读取 capabilities 和相关档案，用 `creative_context_resolve` 传入 taskKind、language，以及已知 brandId、seriesId、projectId、characterIds、lookIds。
2. 返回冻结快照 id、有效规则、人物参考、被覆盖的偏好、conflicts、unresolved、missingInputs 和 reviewRequired。解析会写本地快照，需要 write 权限，不产生生成任务。
3. Agent 使用实际参考素材和规则组织创作，将快照 id 作为 `creativeContextId` 传给 `workspace_request_save`、`workspace_plan` 或 `workspace_commit`。请求后续补充会保留该 ID。
4. `workspace_commit` 检查冲突、必需缺口、未知硬规则条件及上述确定性约束，再把完整规则快照和检查结果保存进作品 revision。编辑默认沿用父版本快照，恢复版本使用被恢复版本的快照。采用新规范需显式重新解析并提交新 ID。
5. 视觉与声音规则在结果中保持 unverified，需要真实审阅。人物和参考有变化时，生成仍须检查模型能力并按实际输入重新报价。

服务器不从自由文本自动建立人物档案，也不会给未传 creativeContextId 的旧调用强行注入全库规范。MCP 指引要求 Agent 在新创作前解析上下文；已配置的网页创作模型可收到显式选择的快照，本地规则规划器不负责把任意审美要求自动转换成画面。低层生成接口仍使用原有参考和报价契约，不能把规范库当成所有生成入口的自动质量保证。

当前没有新增工作台规范管理页、专用导入导出或跨设备同步。通过 MCP/HTTP 可管理本地库；备份仍需一起备份数据库与素材目录。

## 验证

```sh
pnpm exec vitest run tests/creative-memory.test.ts
pnpm exec tsx scripts/verify-creative-memory.ts
```

第二条命令启动临时本地服务，通过真实 MCP 客户端创建规范，停止并重新启动进程，验证规则仍可读且可增量更新。使用独立临时数据目录和随机端口，完成后清理，不修改正在使用的数据库，也不调用付费供应商。
