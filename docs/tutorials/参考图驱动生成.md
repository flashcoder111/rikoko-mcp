# 从参考视频到图生图，再到视频

rikoko 的参考改编流程是：分析原片 → 提取构图帧 → 用目标人物、产品等参考图编辑分镜图 → 检查分镜图 → 用已通过的图生成视频 → 回填剪辑工程。视频优先选择满足输入要求的 MiniMax 档案。每个付费步骤分别报价，准备、审阅和本地剪辑不调用生成供应商。

## 结构化数据与素材的对应关系

| 数据                                                   | 使用方式                           | 输出                                       |
| ------------------------------------------------------ | ---------------------------------- | ------------------------------------------ |
| v2 分析的 `source`、`shots.id/startMs/endMs`           | 校验原片哈希，在所选镜头内抽帧     | 原片构图参考图，带源素材与请求时间         |
| `shots.description/framing`、`visualStyle.description` | 提供画面描述和构图约束             | `imagePrompt` 初稿                         |
| 目标 `references` 的 `assetId/role/instruction`        | 指定人物、产品、场景、风格各自作用 | 图生图的有序图片列表                       |
| `shots.action/cameraMotion`、目标 brief                | 描述需要发生的动作、镜头运动和目标 | `videoPrompt` 初稿                         |
| 明确选择的 `motionRange`                               | 从原视频裁切真实片段               | 可选动作参考视频；不会仅凭文字捏造动作素材 |
| `evidenceIds/unknowns/coverageGaps`                    | 保留依据和未确认信息               | 可追踪的 `storyboard` 记录                 |
| `review.imageAssetId/sha256/checks`                    | 确认目标画面并绑定内容             | 视频生成所用的已审阅图片                   |

图生图默认把 **Image 1 作为构图参考**，后续图片按输入顺序标明身份和产品。原片人物不会自动变成目标人物；更换人物、产品时应提供对应素材和明确要求。生成提示词由宿主 Agent 编写或改写；未提供时使用结构化信息生成初稿，不会暗中调用另一个文字模型。

选帧默认取镜头开始后约 100 毫秒以内的位置。它只是构图草稿，不是最佳帧检测，也不是经人工确认的目标首帧。可指定 `frameTimeMs`；模型估计的镜头时间和 FFmpeg 的请求时间不应被描述成逐帧精确标注。

## 配置兼容的模型档案

把 `config/models.reference.example.json` 的 `providers` 条目合并到现有 `mode: "custom"` 配置，保留已有分析连接。用环境变量 `RIKOKO_CONFIG_FILE` 指定配置文件。不要用示例覆盖已有凭据或连接。

示例包含以下映射，均采用 fal 适配器、读取服务端 `MY_FAL_KEY`：

| 档案                            | 模式                 | 供应商端点 / 参考字段                                                            |
| ------------------------------- | -------------------- | -------------------------------------------------------------------------------- |
| `nano-banana-storyboard`        | `image_edit`         | `fal-ai/nano-banana-2/edit` / `image_urls`                                       |
| `minimax-storyboard-i2v`        | `image_to_video`     | `minimax/h3/image-to-video` / `image_url`                                        |
| `minimax-storyboard-first-last` | `first_last_frame`   | 同上 / 独立的 `image_url`、`end_image_url`                                       |
| `minimax-storyboard-references` | `reference_to_video` | `minimax/h3/reference-to-video` / `reference_image_urls`、`reference_video_urls` |

这些连接默认关闭，`maxCostCents=100` 是占位值，**不是实际报价**。核对供应商权限、真实参数和费用上界，填写 `priceVersion` 后才能启用 `enabled` 与 `hardBoundConfirmed`。通过 fal 接入 MiniMax 使用 fal Key；此配置不是 MiniMax 原生协议。

视频示例固定 5 秒 / 768P，表示一个可报价规格，不是 MiniMax 的能力上限。可按实际任务配置不同的供应商支持规格和费用；`parameters.duration` 与 `generationInput.outputDurationMs` 必须一致，改变规格后重新报价。分镜工具会拒绝比目标镜头短的档案，不会自动降质、缩短动作或删除参考素材。预览与成片可使用独立档案，复用已通过的图；本次没有重写参数选择和计费系统。

`generationInput` 还声明各参考字段的角色、数量、媒体类型、大小、像素及片段时长限制。示例限制是本地档案的保守约束，供应商仍可能有额外要求。所有参考合计最多 12 个、40 MiB；示例动作视频每个 2–15 秒、合计最多 15 秒。超过限制时明确报错，不默默截断。首帧档案必须有首帧，首尾帧档案必须分别提供两张图，避免上游退化为纯文生视频。

协议依据：[Nano Banana 2 编辑接口](https://fal.ai/models/fal-ai/nano-banana-2/edit/api)、[MiniMax 首帧接口](https://fal.ai/models/minimax/h3/image-to-video/llms.txt)、[MiniMax 多参考接口](https://fal.ai/models/minimax/h3/reference-to-video/llms.txt)。配置须以供应商实际可用服务为准；文档字段核对不等于付费验收。

## 一次分镜调用

先按 [参考视频分析](参考视频分析.md) 得到 `ANALYSIS_ASSET_ID`，读取镜头及证据。下面的 ID 都应替换为当前账户实际素材 ID。

1. 本地准备一个镜头：

   ```json
   {
     "analysisAssetId": "ANALYSIS_ASSET_ID",
     "brief": "保留原片的产品展示构图，换成我们的人物和白色瓶装产品",
     "references": [
       {
         "assetId": "PERSON_IMAGE_ID",
         "role": "character",
         "instruction": "保持此人物的脸和服装"
       },
       {
         "assetId": "PRODUCT_IMAGE_ID",
         "role": "product",
         "instruction": "保持瓶身、标签与比例"
       }
     ],
     "shots": [
       { "sourceShotId": "shot1", "durationMs": 5000, "frameTimeMs": 500 }
     ],
     "idempotencyKey": "storyboard-v1"
   }
   ```

   调用 `reference_storyboard_prepare`，返回 `storyboard`，包含 `id`、`version`、每个镜头的 `frame`、`references`、`imagePrompt`、`videoPrompt`。`frameTimeMs` 必须落在该镜头内；需动作参考时显式增加 `motionRange: {startMs,endMs}`，区间应与该镜头重叠且不超过原片和 15 秒。`durationMs` 是目标时长，不修改原片时间；省略时沿用原镜头时长。一次最多 12 镜头；超时可分批准备。

2. 图生图报价：

   ```json
   {
     "storyboardId": "BOARD_ID",
     "expectedVersion": 1,
     "sourceShotId": "shot1",
     "stage": "image",
     "model": "nano-banana-storyboard"
   }
   ```

   调用 `reference_storyboard_quote`；可传 `prompt` 覆盖该次提示词。返回 `quote` 和规范化的 `input`。用户同意报价后，将 **原样 input**、`quote.id`、稳定的幂等键交给 `job_submit`。用 `record_get(type="job")` 查询原任务，不通过重新提交查询进度。

3. 真正查看生成图，再记录检查：

   ```json
   {
     "storyboardId": "BOARD_ID",
     "expectedVersion": 1,
     "sourceShotId": "shot1",
     "imageAssetId": "GENERATED_IMAGE_ID",
     "decision": "accepted",
     "checks": { "identity": true, "product": true, "composition": true },
     "notes": "已查看图片：人物、瓶身标签与构图符合要求"
   }
   ```

   调用 `reference_storyboard_review`，返回新版本。上面的检查结果仅是调用格式示例，不能未看图照抄。此工具只记录用户或具备视觉能力的 Agent 的检查，不会自己判断图片。纯文本宿主需获得用户或视觉工具反馈；不适用的检查填 true 并说明原因。不合格用 `rejected`，再单独报价重做图片。

4. 用最新版本报价视频：

   ```json
   {
     "storyboardId": "BOARD_ID",
     "expectedVersion": 2,
     "sourceShotId": "shot1",
     "stage": "video",
     "model": "minimax-storyboard-i2v"
   }
   ```

   没有动作片段时可选首帧模式，实际把通过检查的图作为 `image_url`。选了动作片段时使用 `minimax-storyboard-references`：Image 1 是已通过的目标图，其后是人物和产品参考，Video 1 是裁切的动作片段。原片构图帧不再直接混进视频身份参考。模型不接受所需角色或数量时拒绝报价，不能丢掉素材换成文生视频。

5. 同意视频报价后提交，完成后将视频素材 ID 填入 `reference_adapt.replacements`：

   ```json
   {
     "analysisAssetId": "ANALYSIS_ASSET_ID",
     "title": "我们的产品视频",
     "replacements": [
       {
         "sourceShotId": "shot1",
         "assetId": "GENERATED_VIDEO_ID",
         "durationMs": 5000,
         "text": "产品展示"
       }
     ]
   }
   ```

   把返回的 `composition` 交给 `workspace_commit`，沿用本地字幕、转场、音轨编排和渲染能力。`reference_adapt` 默认按原片镜头长度剪辑；修改过目标时长时也应在 replacement 中传同一 `durationMs`。单纯改字幕、排版、时间线无需再次生成图片或视频。

用 `record_get({type:"storyboard",id:"BOARD_ID"})` 恢复中断的流程。每次审阅都会增加版本并使旧报价失效；已通过的图默认复用，只有显式 `regenerate:true` 才重报图生图。已经交给供应商的任务不会因随后改了审阅状态而自动取消，需使用现有任务取消流程。

## 底层能力与边界

- `generate` 契约新增 `mode`、有序 `references:[{assetId,role}]` 和可选的分镜关联。未声明参考能力的旧模型继续支持原有文字输入，不能接受参考素材。
- 分镜工具当前编排 `image_edit` → `image_to_video/reference_to_video`。底层契约也支持 `first_last_frame` 和 `video_to_video`；前者需手动准备首尾帧，后者需配置真实视频编辑端点，不能仅改模式名称宣称模型支持。音频角色 `voice` 可由声明了音频输入的档案使用，本示例未启用。
- 提交只接受当前账户素材 ID。报价绑定素材哈希、字节数和角色；提交和 Worker 再次核对，不能用另一个账户的图或改掉已报价参考顺序。
- fal 使用本地存储时，Worker 在内存中构造有界媒体 data URI；受控对象存储可以提供短期 HTTPS URL。Replicate 当前需要具有 `providerUrl` 的对象存储。任务记录不保存这些传输用 data URI 或签名链接。
- 自有与官方模式均可使用参考生成。官方模式要求云端运行时 0.1.3 和兼容模型档案，先上传并映射真实素材；不把本地素材 ID 直接交给官方网关，也不自动转用个人账户。
- 本次不提供独立的 Studio 分镜图审阅界面；通过 MCP 在原宿主会话内完成编排。参考片段、生成图和生成视频仍是普通媒体资产，可进入现有工作台。

## 验证

`tests/storyboard-generation.test.ts` 使用真实本地 FFmpeg 抽帧、裁切和最终渲染，供应商响应由测试模拟，验证素材回填和完整任务流程。`tests/generation-input.test.ts` 覆盖参考模式、字段映射、顺序、媒体限制和不安全地址。测试不会消费供应商额度，也不证明真实人物一致性、产品还原度或生成效果。

## 官方通道更新（2026-10-14）

官方图生图、首帧、首尾帧和多参考生成现在通过私有素材上传与报价映射接入。需要云端运行时 0.1.3 及匹配输入角色的可用模型档案。仅有文生视频档案仍不能执行参考生成；不自动换供应商。分镜保存、审阅和版本检查在本地，提交官方任务后若改变审阅决定，应取消原任务并重新报价。官方参考视频分析仍是独立未接入能力。
