# Commands and model selection

Present command help and model catalog responses in English; other conversation follows the user’s language. Exact model IDs come from capabilities.

## Commands and multiple models

rikoko's current product model integrations use fal.ai as the upstream channel. MiniMax, Seedance and other brands are model choices within that channel, not separate credentials or automatic provider fallback. Use the configured official gateway or custom fal connection; do not propose brand-native keys or switch to another upstream because a selected model is unavailable. Future models require verified fal endpoint profiles before being advertised as available.

Use natural language mentioning rikoko; no installed Skill or slash menu is required. Interpret following text as the same subcommand, for example `rikoko models` or `rikoko model <exact-id>`. Also accept `/rikoko /model <exact-id>` when forwarded by the host. Do not register or claim ownership of global host commands such as `/model`; they may control the host's own LLM. In the studio composer the equivalent command is `/model <exact-id>`. Read `capabilities.commands` for the shared vocabulary and `capabilities.providers` for the current catalog.

| Subcommand                                  | Behavior                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `help`                                      | Show concise syntax and examples from the command catalog; no planning, render or purchase.                                                                                                                                                                                                                                                 |
| `models`                                    | Read capabilities and group actual models into video, image, speech (kind=audio, category=speech), and other audio. Show IDs, names, available status, fixedParameters and declared reference requirements. Do not invent future model availability.                                                                                        |
| `model <id>`                                | Check the exact ID in the current catalog, preserve the active brief, and record the selection under its role. Video, image, speech and other audio each retain their own model choice; changing one never overwrites another. Unavailable or unknown IDs leave the previous choice unchanged. Never silently substitute a different model. |
| `model auto`                                | Clear only the active role's explicit selection (video if no role is active). Prefer compatible Seedance Mini for face-free video. Present/unknown faces block every Seedance variant; recommend MiniMax, offer Kling, and obtain or reuse the user’s explicit selection. If no compatible preferred model exists, explain the gap and ask before switching.                                                                                                 |
| `video`, `image`, `speech`, `audio`, `edit` | Set the requested operation; preserve existing brief, assets and model selections for other roles. These commands alone do not start a job.                                                                                                                                                                                                 |
| `brief <text>`, `style <text>`              | Add requirements to the active request. A later explicit correction supersedes the corresponding earlier requirement.                                                                                                                                                                                                                       |
| `reference <purpose>`                       | Record how supplied media should be used (e.g. character, product, first frame, motion, style). Import accessible attachments and bind their actual asset IDs to supported roles; the text alone is not a media import.                                                                                                                     |

For brief, requirement, mode or model updates, resume `workspace_request_get` when a request exists, then append a concise message through `workspace_request_save` using its current requestVersion. Preserve the original intent, existing asset IDs and remaining missingInputs; do not clear gaps without checking them. A first model-only update can start a saved request and ask for the creative brief. These commands prepare the request, not authorize rendering, paid planning or generation. Persist explicit model ID and target specs in request messages, read them before forming later operations, and use that ID in the actual submitted input. New provider profiles, including future Seedance models, come from the catalog; no hardcoded endpoint, pricing, duration or reference support is implied.

## Natural-language parameters

Users describe duration and aspect ratio in ordinary language, e.g. “Create a 15-second vertical video in 9:16”. Do not offer duration/aspect slash commands or ask users to write API parameters. Normalize the description into the appropriate operation's parameters: video duration/aspect, image aspect/resolution, speech text/language/voice, or music/sound requirements. Separate final edited-video duration from individual generated-clip duration. Keep independent model choices for each stage of a combined image + video + voice workflow.

Inspect `capabilities.providers[].fixedParameters` for public fixed specifications such as `duration`, `aspect_ratio` and `resolution`, plus `generationInput` for reference constraints. Read `allowedParameters` for per-shot overrides and call `generation_prepare` with supported values. Undeclared parameters remain fixed; profiles without overrides use `generate.parameters={}`. Never pretend that text added to the prompt changes its duration or aspect ratio. Missing metadata is unknown, not support for arbitrary values. If the chosen profile does not fit, resolve that gap before submission. For speech use the existing `tts` operation with explicit model, text, language and voice; use the transcript operation for recognition. Voice preferences and language belong to speech operations, not video-generation parameters. Preserve the exact normalized operation through preparation and submission.

Before submission, re-read capabilities and validate model kind, availability, reference mode/roles and resolved output specifications against the latest requirements. Missing references are concrete missingInputs, not grounds to drop references or switch to text-to-video. A model-only preference change does not request generation. Submit the prepared input directly with job_submit within the requested task and any explicit spending limits. Changed inputs require fresh preparation; no separate price confirmation is required by default.
