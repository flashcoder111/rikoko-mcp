# Model writing

Model writing translates a chosen direction into the language and input conventions of an actual model/interface. It does not choose the work's format or replace craft decisions.

Start with `rikoko_guide {topic:"models/prompt-writing"}` for compiler and reference-delivery instructions. `rikoko_guide {topic:"models/seedance-mini"}` adds sourced Mini API conventions and bounded Seedance 2.0 family lessons. `rikoko_guide {topic:"models/minimax-h3"}` adds H3 speech/reference writing and distinguishes official rewrite conventions from actual endpoint inputs. Their examples are authored adaptations, not new empirical trials.

Model entries declare exact configured `modelIds` and, where applicable, input `modes` in catalog scope. The reader selects them only on an exact match; a model family name does not establish compatibility. Mode-limited entries are withheld when mode is unknown. General writing remains available, with `modelCoverage=general_only` when no specific entry matches. Custom renamed profiles need a reviewed catalog mapping; do not infer one from a similar name. A specific reading path is documentation coverage, not proof that the profile accepts every mode described in the page. Read its actual capabilities. Reading never changes the selected provider/model or bypasses its capabilities.

Preserve source title, URL, relevant version and limits with each external lesson. `official_documentation`, `external_example` and `rikoko_tested` identify different evidence origins, not mandatory promotion steps. Official or creator knowledge may be used directly with accurate attribution; do not relabel it as a rikoko trial. No new generation is required merely to add a sourced entry.
